# Disabled Vercel Hobby adapter

This is code preparation for personal, non-commercial use. It does not deploy, provision a database, store credentials, activate a schedule, or establish hosted reliability. All example permissions are false. The existing local launcher and its session-only permission remain separate.

## Execution contract

- Node.js route `GET /api/cron`, dynamic/no-store, `maxDuration=300`. Requires verified Vercel production + Fluid Compute, the exact HTTPS `STUDIO_ORIGIN`, an approved network PostgreSQL connection, and a distinct strong cron bearer credential. Preview and partially configured Vercel environments fail closed.
- One daily schedule only. `vercel.hobby.example.json` is an inert example, **not** `vercel.json`. Do not activate it without the owner's separate hosting, scheduler and credential approvals. Never add frequent jobs, self-pings, request chaining or an external scheduler to evade Hobby limits.
- The daily runner makes at most 12 checkpoint attempts and uses a 240-second logical work budget. It starts no new checkpoint with fewer than 80 seconds left. Individual provider requests have a 60-second timeout. The platform's 300-second termination is the outer bound; slow database operations or network failure can still interrupt a run.
- Migration 009 records one attempt per UTC day and a 360-second singleton lease. Concurrent deliveries and same-day repeats cannot start another batch. A later day can release a stale lease and resume only safe persisted checkpoints. In-flight or unknown usage remains reserved and blocks further work; it is never silently replayed or refunded.
- Every checkpoint rechecks reviewed runtime configuration, calendar activation, budget and unresolved accounting. Existing local queues do not inherit hosted authority: exact owner-cleared evidence is required. A preexisting scheduled task without the hosted timing proof is blocked for explicit review. Its frozen content brief is not rewritten by replanning; cancel it and deliberately choose a new future slot when needed, rather than replaying that slot. Hosted owner `/step` requests are disabled; the local polling worker is not a hosted scheduler.
- New hosted calendar settings require a 120–336-hour generation lead. Existing dates and settings are never changed automatically. Actual stored entries must provide at least 120 hours before their earliest platform post, leaving 72 hours before the fixed 48-hour review deadline. Late catch-up is visible and allowed only before the review deadline. Agent revisions inherit the deadline. Five days is a scheduling cushion, **not a completion guarantee**: backlog, slow responses, failed daily delivery or exhausted budget may still require rescheduling.
- The dashboard shows recent batch status and checkpoint counts. It does not manufacture execution history, exact-hour delivery, reach, or publishing. Final factual review and exact-version approval stay with the owner. Publishing remains disabled.

## Optional pricing validity, still disabled

Default pricing verification remains valid only on its exact UTC verification date. Unattended operation can use an **explicitly approved** bounded review window: set `pricing_window_authorized=true` and `pricing_valid_until` to at most six dates after `pricing_verified_date` (seven UTC calendar days including the verification day). Missing, future, invalid, reversed, too-long or expired windows block calls. The code does not extend or renew a window automatically, update prices, or imply a provider price guarantee.

Before enabling a window, recheck the exact configured model's official standard/default-tier prices and approve the review interval. Set a calendar reminder or perform a manual review before expiry; no reminder was created by this change. A price/tier/model anomaly still pauses execution and retains uncertain accounting. The combined IST-month warning remains US$10, cap US$15 with US$1 internal buffer; these are internal reservation controls, not a guarantee of the external invoice or hosting/database charges.

## Official limits checked 2026-10-12

- [Cron usage and pricing](https://vercel.com/docs/cron-jobs/usage-and-pricing): Hobby supports once-daily frequency and hourly precision. A configured hour can run anywhere within that hour.
- [Function duration](https://vercel.com/docs/functions/configuring-functions/duration): Hobby with Fluid Compute has a 300-second maximum.
- [Cron management](https://vercel.com/docs/cron-jobs/manage-cron-jobs): bearer-secret header, no automatic failure retry, possible duplicate delivery, and concurrency locks/idempotency requirements.
- [Vercel Authentication](https://vercel.com/docs/deployment-protection/methods-to-protect-deployments/vercel-authentication): verify current All Deployments availability/settings in the approved account. Its interaction with cron remains an integration check.

No hosted browser, network PostgreSQL, Vercel cron or paid OpenAI test has been performed for this adapter.
